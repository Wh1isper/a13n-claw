## Project and Inbox

Create one dedicated Claw service account in the Workspace with the `builder` role (`read`, `run`, and `write`, without `admin`), and select it with a native Agent. Control, Main, Workers, and fresh Schedules share this identity. Their Runs can use Workspace write through authorized Service operations; the account is not run-only. Interactive operators retain their own authorization. Fresh Schedule requests record the operator separately from the Service Account's native Schedule audit. You can select its resources immediately or finish setup under **Workspace Settings → Claw settings → Project**. Select an existing Environment or create one from a template. For a Browser, create or attach one in native Console and select that instance in Claw. The Inbox accepts messages before an Environment is ready; Main starts when it can execute. Browser is optional. Set a heartbeat interval in seconds (`0` disables it) and independent limits for unread items and retained read items. See the [field reference](./configuration-reference.md).

The Project has its own Memory Space and records the Environment and Browser instance IDs. Start, stop, and recovery are native Service operations. A stopped resource can keep its binding; preserve files, CLI configuration and browser profiles according to the provider's retention guarantees. Rebinding applies to later Runs and does not transfer existing state. Archive active or paused fresh-Thread schedules before changing either Project resource binding. Before changing the Environment, finish or cancel active or waiting Main and shared Worker Runs.

## Headless operation

Claw endpoints use the Service origin, `X-Workspace-ID`, and a Service credential, under `/api/v1/apps/a13n.claw/`. Use `GET /claws` for discovery, `PATCH /claws/{claw_id}/project` to change resource bindings, and `POST /claws/{claw_id}/input` to submit `{ "content": "…" }`. Send an `Idempotency-Key` when submitting input; reuse it only for the same body. Use `GET /claws/{claw_id}/deliveries` and its detail endpoint for retained delivery history. Filter retained deliveries with `inbox_state=unread`, `read`, or `expired`. Use `POST /claws/{claw_id}/agent-revision/sync` to sync the Agent revision and `DELETE /claws/{claw_id}` to archive a Claw. The Service OpenAPI document lists installed endpoints. To add or edit a connector, send `name`, `kind`, `enabled`, and the platform-specific `config` to the connector collection or resource, with an optional write-only `credential`. Omit `credential` to keep the stored value, or send `null` to clear it. When `egress_primary` is `true`, include `egress_environment_id` with the Project Environment ID you reviewed; a missing or stale ID is rejected. `POST .../check` returns the connection state and any secret-free diagnostic code, with an HTTP status when available. `DELETE` on the connector resource leaves its delivery history intact.

## Connector credentials

Configure Service credential encryption on both Control and Worker before saving connector credentials. For a single host, set `A13N_ENCRYPTION__KEY_FILE` to a path on a persistent volume; Service creates the key on first start. On separate hosts, configure the same key ring on both. Back up the key separately from the database.

Claw reads only its encrypted stored credential. When moving from a deployment that used `CLAW_SECRET_DIR`, save and verify the credentials through Console before upgrading, then remove the obsolete file mounts.

To authorize Project CLI access, select **Use for Project egress** on one enabled connector per platform. Claw supplies a non-secret placeholder through Service Controlled HTTPS Egress; the proxy injects the credential into approved host headers. An unconfigured Thread binding is initialized with controlled egress and public destinations. Existing explicit destination policies are preserved or the change is rejected; Claw does not widen them. Shared Worker Sessions can inherit this capability. Fresh Scheduled Threads report to Main and do not capture these connector credentials in their Schedule definitions. Changing the Project Environment requires reauthorization.

Lark uses the encrypted App secret in Control to obtain and refresh a short-lived tenant token. GitHub exposes `GH_TOKEN` to `gh` and compatible API requests; Git HTTPS Basic authentication is outside this integration. Replacing a credential for the same selected connector and host rotates its existing Service credential without unbinding the Session. Removing a credential or changing its host queues revocation and Session cleanup. If access must end immediately, revoke the original credential at the provider.

CLI maintenance needs a Linux shell with `timeout`, `curl`, `tar`, and `sha256sum`, and network access to the official GitHub releases. Open **Claw settings → Project → Platform CLIs** to see the last probed versions for the bound Environment. **Update CLIs** queues the latest official release for the current Environment. A queued update waits for the next Main execution; if heartbeat is disabled and Main is idle, submit work to the Inbox to start a Run. The button does not start an Agent on its own.
